# Расписание бота (ScheduleProvider)

`core/schedule_provider.py` — реальная реализация протокола
`StateProvider` (из `core/layers.py`). Бот знает, чем «занят» прямо
сейчас, исходя из локального времени, и это попадает в промпт
state-слоем. В будущем это же состояние можно завязать на готовность
отвечать и задержку ответа (Этап 8) — в рамках этого этапа только
текст в промпте.

## Конфиг `config/schedule.yaml`

Единственное место правки занятий по времени суток.

```yaml
local_tz_offset_hours: 3   # UTC + сдвиг = локальное время бота
default_activity: "..."
slots:
  - start: "09:00"
    end: "18:00"
    activity: "..."
```

- `local_tz_offset_hours` — часовой сдвиг от UTC. Редактируемый
  параметр, в коде не хардкодится. Системная таймзона хост-машины
  не используется вообще.
- `default_activity` — используется, если текущее время не покрыто
  ни одним слотом (защита от дыр в конфиге).
- `slots` — список слотов. Время `HH:MM`, 24-часовое, строго две
  цифры на час и минуты.

## Семантика слотов

- Диапазон **`[start, end)`**: 07:00 уже входит в слот «07:00–09:00»,
  09:00 — уже нет.
- Слот с `start > end` (например `23:30–07:00`) — переход через
  полночь: покрывает `[start, 24:00) ∪ [00:00, end)`. Это норма, а
  не ошибка конфига.
- **Первое совпадение побеждает** — порядок слотов в файле значим.
  При пересечении слотов (overlap) работает первый по порядку.
- Слоты НЕ обязаны покрывать все 24 часа стык-в-стык: дыры закрываются
  `default_activity`, а не падением.

## Валидация при загрузке

Проверяется ОДИН раз в `__init__` (а не при каждом `render()`),
ошибки падают при старте процесса как `ScheduleConfigError`:

- формат времени `HH:MM` для всех `start`/`end`;
- `default_activity` не пустая;
- минимум один слот;
- корень YAML — словарь, файл существует.

Сознательно НЕ проверяется полное покрытие 24 часов и отсутствие
пересечений слотов — это over-engineering для этого этапа. При
пересечении побеждает первый слот.

## Время

`_current_local_time()` = `datetime.now(timezone.utc)` + смещение из
конфига → `time()`. Никакой зависимости от таймзоны хост-машины и
никакой SQLite-магии `datetime('now')` из старого бота — всё явное
и тестируемое.

## render()

Возвращает `"Сейчас ты: {activity}."` и **никогда не `None`** — у бота
всегда есть состояние, хотя бы дефолтное. `addressee_nick`
игнорируется (расписание — общее состояние бота, не завязано на
собеседника), но параметр остаётся по интерфейсу `StateProvider`.

## Тесты

`tests/test_schedule_provider.py` подставляет текущее время
(мокает `_current_local_time`) — тесты не зависят от реальных часов
CI. Покрыты: границы слотов `[start, end)`, переход через полночь,
дыра в конфиге, пересечения (первый слот), невалидные конфиги,
смещение часового пояса.

## Заметка про заглушку

`StubStateProvider` в `core/layers.py` остаётся НЕТРОНУТЫМ — он нужен
юнит-тестам `PromptBuilder` из Этапа 2. В `cli.py` (и ручном евале)
подключён реальный `ScheduleProvider`. Замена «в проде» не равна
удалению заглушки.
