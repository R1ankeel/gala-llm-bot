# Карточка персонажа (character.yaml)

Один файл YAML описывает «кто это» и «как говорит». Собирается
в единый неразрезаемый identity-блок функцией
`build_core_system_prompt` из `core/character_loader.py`.
Этот блок всегда идёт первым в промпте и никогда не отбрасывается.

## Схема

Все поля обязательны, кроме `deflect_style` (см. таблицу).

| Поле | Тип | Смысл |
|---|---|---|
| `name` | string | Имя персонажа |
| `short_bio` | string | 2–4 предложения: кто это |
| `speech_style` | list[string] | Конкретные правила речи (короткие фразы, сленг, эмодзи…) |
| `boundaries` | list[string] | Что персонаж НЕ делает (домашка, код, «энциклопедия»…) |
| `refusal_style` | list[string] | 3–5 примеров, КАК персонаж отказывает (в характере) |
| `deflect_style` | list[string] | 3–5 примеров, КАК персонаж уклоняется от погоды/науки (тон «а я почём знаю», а не раздражение) |
| `example_dialogues` | list[{user, bot}] | 5–8 пар реплик — few-shot голоса |
| `never_do` | list[string] | Жёсткие технические запреты (не начинать с ника, не выходить из роли…) |

Обязательные: все поля кроме `deflect_style` (его отсутствие не
ломает загрузку — `search_guard` подставит дефолтную фразу).

## Примечания

- `speech_style`/`boundaries`/`refusal_style`/`never_do` — каждое
  значение строка; рендерятся в промпт дословно (см. тест
  `test_core_system_prompt_contains_all_fields_verbatim`).
- `example_dialogues` рендерятся как
  `Пользователь: <текст>` / `<Имя>: <текст>`.
- `short_bio` можно задавать блочным литералом `|`, чтобы переносы
  строк не зависели от редактора.
- Guard-блоки (отказ от «ассистентских» задач и уклонение от
  погоды/науки) рендерятся отдельными слоями — см. `docs/task_guard.md`
  и `docs/search.md`.
